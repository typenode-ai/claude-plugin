# Get started

First compare the request with the advertised Typenode tool capabilities. For a clearly unsupported task, explain the limitation and stop before calling any Typenode tools. For supported work, continue below.

1. Call `start` for the authenticated workspace and orientation. Report the connected workspace name and ID as display data. This read changes neither account state nor available access.
2. Identify the person's goal: build a workflow or MCP tool, use a template, configure a server or access, set up an integration or environment, publish a workflow, or diagnose a run. Explain only the relevant work and the tools actually available. Ask for the goal if it is missing.
3. If a connection or setup step blocks progress, read [handoffs](references/handoffs.md). Guide the actual missing step, then verify its designated outcome. For a tool failure or uncertain result, read [repair](references/repair.md).
4. Finish with the connected workspace, the next concrete task and any access or setup blocker. Continue the appropriate task when authorized; orientation need not run before every later request.

Use Build for workflow logic and templates, Configure for MCP servers, access, integrations and publication, and Debug for a particular run. The plugin's guidance cannot create authority or replace the person's OAuth consent.
